# 热念 · 微信小程序隐私保护上线清单

更新时间：2026-09-28

## 1. 当前实际使用的隐私相关能力

| 能力 | 代码位置 | 用途 | 微信后台隐私指引 |
|---|---|---|---|
| `open-type="chooseAvatar"` | `pages/settings/settings.wxml` | 用户主动选择微信头像，展示给绑定关系中的双方 | 必须按后台实际提示声明“头像”对应项 |
| `wx.chooseMedia` | 日常、相册、私密备忘录 | 用户主动选择照片/拍摄照片后上传 | 必须按后台实际提示声明“选中的照片/媒体”对应项 |
| `wx.saveImageToPhotosAlbum` | `pages/albums/albums.js` | 用户主动把一张已展示的照片保存到系统相册 | 仅在用户点击保存时调用；按后台/审核提示配置对应能力 |
| `wx.requestSubscribeMessage` | `pages/settings/settings.js` | 用户主动允许一次每日分享提醒或想念提醒 | 一次授权对应一次通知，不作为默认持续订阅 |
| 微信 OPENID | `renianApi` 服务端 `getWXContext()` | 识别当前微信用户并隔离双人关系/数据权限 | 在隐私说明中披露账号识别用途 |

## 2. 应在《小程序用户隐私保护指引》中说明的数据

除微信后台根据隐私接口提示要求勾选的标准项外，指引正文应与实际业务保持一致：

- 账号标识：使用微信提供的用户标识识别当前账号，不设置独立账号密码。
- 头像：仅在用户主动选择后保存，用于双人关系内的头像展示。
- 照片：用户主动选择的照片用于日常、相册、私密备忘录或头像功能；上传图片会先生成审核副本进行内容安全检查。
- 双人共享文字：日常文字、相册名称/评论、共同约定、心愿券、公开心情会保存到双人空间并向绑定的另一方展示。
- 私密备忘录：文字和关联图片仅本人可读取，不向绑定的另一方展示。
- 提醒设置：仅在用户主动授权微信订阅消息后保存提醒状态/次数，用于相应提醒。
- 安全与运维：必要的操作记录、版本号、创建/更新时间用于幂等、防重复提交、故障恢复与安全审计。

## 3. 明确不使用/不应声明为已使用的能力

当前代码未发现：

- 定位/精确位置
- 通讯录
- 手机号获取
- 麦克风录音
- 后台定位
- `wx.getBackgroundFetchData` / background fetch 业务调用
- 独立账号密码登录

不要为了消除开发者工具警告而虚构以上采集项。

## 4. 微信公众平台配置

在微信公众平台小程序后台找到“用户隐私保护指引”配置入口：

1. 按实际使用接口补齐平台要求的隐私收集类型。
2. 填写每项用途，措辞应与本文件第 2 节一致。
3. 保存并提交隐私保护指引审核。
4. 若新增/修改了隐私收集类型，重新确认指引已审核生效。
5. 回到开发者工具清缓存并重新编译，在未同意隐私指引的测试用户上触发一次头像/照片功能，确认微信官方统一隐私弹窗出现。
6. 同意后再次触发功能，确认不重复阻断。
7. 设置页点击“隐私保护指引”，确认能通过 `wx.openPrivacyContract` 打开微信正式指引。

## 5. 验收口径

以下全部满足才算隐私项通过：

- 微信后台隐私保护指引已配置并审核生效。
- 首次调用隐私相关能力时，未同意用户会看到微信官方统一隐私弹窗。
- 拒绝后不继续调用需要隐私授权的能力，但小程序其它非隐私功能仍可使用。
- 同意后头像/选图/保存相册等能力正常。
- 设置页可随时打开正式隐私保护指引。
- 控制台即使仍出现 `[wxapplib] backgroundfetch privacy fail`，只要仓库没有 background fetch 调用且业务功能不受影响，不把该框架日志当作业务故障。
