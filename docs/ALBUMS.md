# 共享相册第一版

入口：「我们」→「我们的相册」。双方均可新建相册（名称 1～40 字），每批选择 1～9 张照片，每张不超过 20 MB。支持分页、重新获取预览地址；只有上传者可删除自己的照片。日常新上传的图片会自动归集到系统相册「日常照片」，复用同一云文件并通过引用计数避免重复上传；选图允许微信原生原图/压缩图选择，单张上限 20 MB；相册照片支持保存到手机系统相册。相册归集本身不会增加日常统计或取消当天未分享提醒。

## 在其它设备测试前

本次仅提交代码，没有修改云端配置或部署函数。先拉取修复分支最新提交，保留各设备 Git 忽略的 AppID、云环境配置。

1. 按 `config/database.albums.json` 新建 `v2_albums`、`v2_album_photos`，客户端读写权限均关闭；创建 `album_list` 和 `album_photos` 两个复合索引，等待就绪。这是独立功能扩展，不运行旧数据迁移，不改变旧 V2 集合。
2. 更新 `renianApi`，选择云端安装依赖；现网 3 秒超时可能不足以完成媒体校验，建议按发布文档配置。前端 API 未部署时会提示“相册服务尚未更新”。
3. 编译上传体验版，两账号绑定后从「我们」进入相册。未绑定账号不能读写相册，另一对关系不能读取相册及照片地址。
4. 现有 `mediaCleanup` 可识别删除照片的 cleanup_pending 状态；定时器未启用时只会隐藏照片、标记待清理，不承诺云文件已物理删除。沿用现有存储规则和服务端图片签名校验。

## 失败恢复和验证

- 创建、批量提交、删除使用服务端事务及 requestId 幂等；提交后刷新失败保留原请求，重试不重复。
- 当前关系及本人角色隔离本地待办；选择、上传准备、存储上传、确认进度保存在本机。退出后可重试待提交操作；微信临时图片文件已失效时移除待上传照片并重新选择。
- 未提交或替换掉的上传由现有过期媒体清理流程回收。图片临时地址失败显示可点按的占位，正文列表仍可读取。
- 测试：A 建相册，A/B 各上传多张；双方预览；B 无法删除 A 的照片；A 删除后双方刷新不可见；无权账号访问失败；弱网批量提交和刷新失败重试无重复；超过一页照片继续加载。
- 不包含相册重命名/删除、私密相册、历史日常图片批量回填或视频；新发布及后续编辑的日常图片会自动归集到「日常照片」。

新增 API：album.list、album.create、album.photos、album.addPhotos、album.deletePhoto。身份取服务端 OPENID；不接受客户端传入作者或 coupleId 作为权限依据。

## 本地验收

现有及新增自动化测试共 92 项通过，新增覆盖相册事务、权限、分页、图片失效、删除回收、上传断点恢复和重试身份持久化。Playwright 对相册列表、照片页、上传草稿、待确认、空相册、未绑定及「我们」入口在 320/390/430 px 的 21 项布局检查通过。浏览器模拟结果不能替代微信真机、原生选图及真实云端上传验收。

## 原图、动态照片与保存

- 选图使用 `wx.chooseMedia` 的 `sizeType: ['original', 'compressed']`，由微信原生选择器提供原图/压缩图选择。
- 单张图片前端和云函数统一限制为 20 MB，服务端仍校验真实文件内容与类型。
- 微信小程序标准图片选择接口没有提供稳定的 iPhone Live Photo 成对资源字段；动态照片当前作为静态图片导入，不宣称保留动态效果。
- 相册照片提供“保存”，先下载服务端授权的临时地址，再调用 `wx.saveImageToPhotosAlbum` 写入系统相册；拒绝权限时引导用户打开微信设置。
