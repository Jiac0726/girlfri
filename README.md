# 热念 💕

> 把每天的喜欢、在意和小情绪认真留下来。
> 两个人绑定后共享一份记录：一位是「评价方」，一位是「查看方」。

## 当前功能

| 页面 | 作用 |
|---|---|
| **今日评价** | 评价方每天写一条好评 / 差评 + 备注；查看方只读 |
| **历史记录** | 双方查看全部记录及好评 / 差评 / 总天数汇总 |
| **月报** | 按月查看好评率、日历热力图、高光 / 翻车 / 小作文 |
| **成绩单** | 好评率、连续好评、14 天热力格、本月统计、导出图片 |
| **双人绑定** | 8 位一次性绑定码，建立两人的共享关系和角色 |

## 安全模型

客户端不再直接读写云数据库。

所有绑定和评价操作统一进入：

```
cloudfunctions/renianApi
```

云函数使用 `cloud.getWXContext().OPENID` 获取微信调用者身份，并在服务端检查：

1. 用户是否已经绑定；
2. 是否属于当前这对关系；
3. 关系是否已经激活；
4. 当前用户是不是「评价方」。

所以即使有人修改前端 JS 或伪造 `type / reason` 请求，也不能把自己伪装成另一位用户或绕过角色限制。

## 部署

### 1. 配置小程序和云环境

在 `app.js` 中填写云开发环境 ID：

```js
wx.cloud.init({
  env: '你的环境ID',
  traceUser: true,
});
```

在 `project.config.json` 中填写 AppID：

```json
"appid": "你的AppID"
```

### 2. 创建三个数据库集合

云开发控制台 → 数据库，新建：

```
couples
couple_users
ratings
```

### 3. 关闭客户端数据库直读写

正式使用时，这三个集合都不要再设置成：

```json
{ "read": true, "write": true }
```

应在数据库权限中禁止小程序客户端直接读写。数据只通过 `renianApi` 云函数访问。

云函数属于服务端管理端，因此仍可操作这些集合；鉴权逻辑由云函数自身负责。

### 4. 部署云函数

微信开发者工具中找到：

```
cloudfunctions/renianApi
```

右键选择 **上传并部署：云端安装依赖（不上传 node_modules）**。

`package.json` 已锁定：

```json
"wx-server-sdk": "4.0.2"
```

### 5. 编译并绑定

第一台手机：

1. 打开「双人绑定」；
2. 选择自己的角色：评价方或查看方；
3. 生成 8 位绑定码；
4. 把绑定码发给另一位。

第二台手机：

1. 打开「双人绑定」；
2. 输入绑定码；
3. 加入后自动获得相反角色。

绑定码有效期为 **24 小时**，使用后立即失效。

## 数据结构

### couples

一对关系一条记录：

```json
{
  "_id": "pair_xxx",
  "status": "active",
  "creatorOpenid": "...",
  "creatorRole": "viewer",
  "partnerOpenid": "...",
  "memberOpenids": ["...", "..."]
}
```

### couple_users

用用户 OPENID 作为 `_id`，保存其关系和角色：

```json
{
  "_id": "<OPENID>",
  "coupleId": "pair_xxx",
  "role": "rater",
  "status": "active"
}
```

### ratings

每天一条的唯一 ID 改为：

```
<coupleId>_<YYYY-MM-DD>
```

例如：

```
pair_abcd1234_2026-09-22
```

记录：

```json
{
  "coupleId": "pair_abcd1234",
  "date": "2026-09-22",
  "type": "good",
  "reason": "今天主动做了饭还洗了碗",
  "ratedBy": "<评价方 OPENID>",
  "updatedAt": "<时间>"
}
```

这样既保证**同一对情侣每天最多一条**，也避免不同情侣在同一天发生文档 ID 冲突。

## 旧版数据注意

旧版本的 `ratings._id` 只有日期，例如：

```
2026-09-22
```

这些记录没有 `coupleId`，新版不会自动把它们认领给某一对关系，避免错误归属。

如果已经存在需要保留的真实数据，应确认归属后再做一次显式迁移。具体设计见 `AUTH.md`。

## 常见问题

**Q: 为什么查看方改了前端也不能提交？**

因为最终写入检查在云函数里。云函数会根据真实 OPENID 查询 `couple_users`，只有角色为 `rater` 才能写。

**Q: 为什么绑定后旧记录不见了？**

旧数据没有 `coupleId`，新版故意不自动归属。需要先确认这些旧记录属于哪一对，再迁移。

**Q: 图片成绩单怎么用？**

「成绩单」页底部点「📷 生成热念成绩单」，可以保存到相册或预览大图。

**Q: 一天能写两条吗？**

不能。云端使用 `<coupleId>_<日期>` 作为文档 ID，重复提交只会覆盖当天这一条。

## 当前限制

- 已完成双人绑定后暂未提供“解除关系”按钮，避免误删或产生孤儿数据。
- 旧版记录不会自动迁移。
- 当前“一天”的日期按 UTC+8 计算。

详细安全设计见 [AUTH.md](./AUTH.md)。
